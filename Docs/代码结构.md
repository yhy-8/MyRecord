# MyRecord 代码结构

两端架构：**服务端**是数据中枢（同步 + 鉴权 + 渲染 + 云端 AI），**客户端**是薄记录端
（本地优先写入 + 实时同步 + 查看）。

安全/加密/日志/AI 审核的逐项设计见 [安全、通信与日志.md](./安全、通信与日志.md)。

---

## 1. 总体数据流

```text
客户端输入记录
   │ 1) 本地先落盘（永不回滚）
   │ 2) 尽力即时 push（失败进离线队列 outbox.json）
   ▼
服务端 hub（store.append_entries 按 entry_id 去重合并 → state.json）
   │ 渲染 → data/Records/YYYY-MM-DD.md
   │ 扇出 → 各在线客户端 longpoll 收到增量
   ▼
客户端 apply_delta 补齐本地 + 按 tombstone 移除已删条目
```

客户端只在前台运行时保持一条长连接（长轮询）；启动/手动 `/sync` 时做一次完整对账。

## 2. 客户端（client/）

| 模块 | 职责 |
|---|---|
| `__main__.py` | 入口：`python -m client` → `cli.run_interactive()` |
| `cli.py` | 交互主循环：8 个命令路由；普通输入 → 构造 entry → 写本地 + push；启动 full_sync；长连接后台线程 |
| `identity.py` | 链接凭证（单一共享 token）读写 `credentials.json`；`device_name()` 自报本机名；`make_entry_id(date,ts,text)` 生成设备无关确定性 id |
| `journal.py` | 本地日记渲染与写入：按天 `Records/YYYY-MM-DD.md`；对账 `apply_delta`；tombstone 移除 |
| `sync.py` | 同步客户端：`push_new`/`send_pending`/`pull`/`longpoll`/`full_sync`/`sync_reports`；TLS `verify` |
| `config.py`+`config.yaml` | 本地配置：服务器地址、数据目录、长轮询秒数、`verify`（TLS 校验收信） |
| `file_lock.py` | 跨进程互斥（原子写保护） |

### 客户端本地文件

- `credentials.json`（链接凭证，gitignore）/ `credentials.example.json`（样板）
- `outbox.json`（离线待推送队列）
- `Records/`（本地日记）、`AnalysisReports/`（报告副本）、`Log/`

## 3. 服务端（server/）

| 模块 | 职责 |
|---|---|
| `main.py` | CLI：`run`（起 hub + AI 调度线程，**强制 TLS**）、`token`（单一链接凭证）、`cert`（自签证书）、`import`、`render` |
| `config.py`+`config.yaml` | 监听、数据目录、模型、重试、自动任务、TLS 证书路径 |
| `hub/server.py` | HTTP 同步服务（stdlib ThreadingHTTPServer + ssl 包裹）：`/api/sync/push|pull|longpoll`、`/api/entries/delete`、`/api/status`、`/api/reports`、`/api/admin/*`；Bearer 鉴权 |
| `hub/store.py` | 权威条目存储（`state.json`）：按 entry_id 去重合并、tombstone、垃圾桶、单一链接凭证、全局 version 游标 |
| `hub/auth.py` | 链接凭证哈希（scrypt，加盐、常量时间），只存哈希 |
| `hub/render.py` | 日记文件格式：渲染 entry（含设备名标记）与 tombstone，并反向解析（兼容旧标记） |
| `ai/` | 云端 AI：`settings`、`ai_client`、`journal`（写 `<summary>`）、`agents`、`analysis/`（context/orchestrator/automation）、`file_lock`、`logging_config` |

### 服务端数据空间（`server/data/`，gitignore）

- `state.json` — 权威条目/设备/垃圾桶状态
- `Records/` — 渲染的每日日记
- `Trash/` — 被删正文（垃圾桶）
- `AnalysisReports/` — 报告与自动任务状态
- `tls/` — 自签证书与私钥
- `Log/` — 服务端日志

## 4. 记录格式与 entry_id

每条记录在日记文件中是一块：

```text
<!-- myrecord-id:<id> -->
<!-- myrecord-device:<设备名> -->        （可选，记录自带设备名）
**HH:MM [设备名]:** 正文                  （设备名可见地标在记录行）
```

- **entry_id**：内容派生、设备无关 —— `sha256(date + ts + tag + text)` 前 16 位。同一记录
  在任何客户端算出同一 id，离线多端上线后按 id 去重合并；时间戳参与哈希，避免同一天重复写
  相同句子被误合并。
- **tag**：普通记录无标签（默认空）。仅“引用”等特殊记录带标签（如 `[引用]`）。
- **device_id**：客户端自报本机名（如 `MK8`、`vivo y78`），既存于条目数据，也可见地渲染在
  记录行上，便于区分是哪台设备写的。
- **删除**：写 tombstone 占位（不含正文），正文入垃圾桶，不做硬删除，防“已删条目复活”。

  删除后的占位示例（**只有一行，不含正文**）：

  ```text
  <!-- myrecord-tombstone-id:<id> -->
  ```

  只这一行占位。原正文已移入服务端 `Trash/`（垃圾桶），可恢复。

## 5. 鉴权与传输

- **连接凭证（修改日记所需的超长密码）**：服务端 `token create` 签发唯一共享、超长的随机 token；
  服务端只存 scrypt 哈希。凭证不绑定设备——持有 token 即可用任意客户端同步/修改；设备由各端
  自报本机名区分（`X-Device-Id`）。所有联系服务端的接口（push/delete/pull/longpoll/status/
  reports/admin）都要带 `Bearer <token>`；无凭证只能本地记录，无法把修改传上服务端或拉取/删除
  云端数据。连续鉴权失败 5 次会按设备锁定 60 秒。
- **传输（强制加密）**：服务端**必须**在 TLS 下运行——`server.main run` 未配置 TLS 会拒绝启动
  （禁止明文）。`python -m server.main cert` 让**服务端签发自己的自签证书（公钥）**并填入
  `config.yaml` 即启用 HTTPS 直连；客户端 `config.yaml` 的 `server_url=https` 且 `verify` 指向
  该证书路径校验收信。自签直连，无需反向代理。

## 6. 服务端日志

服务端日志统一写到 `server/data/Log/MyRecord.log`（滚动文件，5MB×2），记录：

- **客户端连接/鉴权**：`auth_failed`、`auth_locked_out`、`auth_missing_device`、`status_request`；
- **对日志的修改**：`sync_push`（推送/采纳条数）、`sync_delete`（在线删除的 entry_id）、`sync_pull`、
  `sync_longpoll`、`report_read`/`reports_list`；
- **AI 报告生成**：`analysis_started/completed/failed`、`agent_start/completed/failed`（每步
  Agent 与 Token 用量）、`daily_summary_validation_failed`、`automation_retry_*`；
- **自动任务调度**：初始化失败、配置无效、scheduler 异常等。

隐私原则：**不记录**日记正文、模型密钥与 token 明文（模型密钥只存哈希指纹且不入日志）。

## 7. 云端 AI 设计与审核（周报/月报）

- **无工具、无联网搜索**：Agent 不能读写文件/数据库/调用工具；所有原始记录与辅助上下文由中控注入。
  搜索配置已移除，测试断言不再有 researcher/planner/搜索阶段。
- **两个 Agent**：`retrospective`（纯文本回顾，短要点分点）与 `reviewer`（最小 JSON
  `{"approved":bool,"feedback":str}`）。
- **审核链 = 确定性校验 + 独立审查者 + 有界修订**：格式/结构确定性校验（禁 JSON/标题/URL/代码
  围栏）→ reviewer 实质审查（事实、时期、身份、来源覆盖、因果越界、心理诊断、套话、教练式命令）→
  不通过则附修改意见让 retrospective 改一次（`agent_revision_limit`）；仍不过则整份失败、旧文件
  不动（原子交付）。
- **防陈旧写入**：总结写入前比对日记内容哈希，生成期间被改则不写旧总结。
- **报告来源标注现状**：正文末尾一行“> 记录依据：日期…”，不做逐条编号；内部来源 ID
  （R-日期-序号）不暴露。目标改为正文数字编号 + 文末来源表（`1：R-YYYYMMDD-aa-bb`），详见
  [安全、通信与日志.md](./安全、通信与日志.md) 第 5 节。

## 8. 同步协议（HTTP 接口）

| 端点 | 用途 |
|---|---|
| `POST /api/sync/push` | 推送新条目（`{entries, version}`） |
| `GET /api/sync/pull?version=N` | 拉取增量 |
| `GET /api/sync/longpoll?version=N` | 长轮询扇出 |
| `POST /api/entries/delete` | 在线删除当天最新一条 |
| `GET /api/status` | 服务端状态 |
| `GET /api/reports` + `/api/reports/<kind>/<name>` | 报告列表/内容 |
| `POST /api/admin/retry`、`/api/admin/model` | AI 任务重试/切换模型 |

鉴权：`Authorization: Bearer <token>` + `X-Device-Id`（客户端自报本机名）。
