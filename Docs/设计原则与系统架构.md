# AgentRecord 设计原则与系统架构

本文说明 AgentRecord 的产品边界、可信数据和模块分工。Agent 调用细节见[Agent 与报告流程](./Agent与报告流程.md)，文件、自动任务和恢复机制见[运行机制与数据](./运行机制与数据.md)。

## 1. 产品目标与边界

AgentRecord 是本地优先的个人记录和周期回顾工具。用户持续写日记，程序生成日记总结、自然周报和自然月报，不要求预先分类，也不把记录过程变成与 AI 的对话。

| 产物 | 输入 | 职责 | 联网 |
|---|---|---|---|
| 日记总结 | 单日日记 | 简洁概括当天重要内容 | 否 |
| 周报 | 一个完整自然周 | 整理回顾，并从记录引出最多五个公开研究问题 | 是 |
| 月报 | 一个完整自然月 | 综合当月记录、近期总结和月内完整周报的回顾段 | 否 |

系统不生成人物画像、心理诊断、分析日报或每日信息简报。月报不重新规划、搜索或扩展周报研究。

## 2. 核心原则

### 2.1 原始日记是唯一事实源

`Records/YYYY-MM-DD.md` 保存用户实际写下的内容。总结、报告和自动任务状态都是可重建的派生数据。普通记录写入不依赖模型、网络、报告生成或自动队列。

### 2.2 模型处理语义，中控处理确定性细节

模型只负责总结、关联、选题、证据综合和审查。程序负责日期、分组、编号、搜索、URL、来源绑定、Markdown、文件名、重试次数、Token 累计和完成状态。

多项任务由中控拆成多次单项调用：每个 Planner 只处理一个记录组，每个 Researcher 只处理一个问题，每个 Reviewer 只审一份正文。模型不返回文档树、来源数组或文件路径。

### 2.3 JSON 只承载控制语义

Planner、Researcher 和 Reviewer 使用最小 JSON 对象，因为它们的结果会改变控制流。Retrospective 和日记总结只返回纯文本，避免用无意义的 `{"text":"..."}` 增加解析失败面。

程序仍严格校验 JSON 字段、类型、枚举和未知字段。合法 JSON 不等于合法业务结果。

### 2.4 完整优先，任务级预算只防异常

程序不按字符数截断或否定已完成正文。提示词要求模型在完整覆盖任务的前提下简洁。每类任务在代码中使用宽松的接口输出预算：日记总结 4096、Planner 1024、Reviewer 16384、Researcher 32768、Retrospective 65536 Token。

接口以 `length` 结束时视为未完整交付。输入上下文另有字符安全边界；输入边界与输出篇幅政策互不替代。

### 2.5 报告状态只在当前进程内流转

报告不读取或写入 SQLite，也不跨运行复用旧正文、Reviewer 结论或搜索证据。一次运行内的正文、证据和 Token 遥测保存在内存中；失败后的下一次运行从冻结输入重新生成。

正式 Markdown 通过同目录临时文件原子替换成功，即代表报告交付。日志失败不会改变报告内容，也不会撤销已交付文件。

### 2.6 信任层级必须显式

送入 Retrospective 和对应 Reviewer 的材料具有相同结构：

```text
facts.current_records          当期原始记录，主要事实依据
facts.referenced_records       用户显式引用的历史记录
context.recent_summaries       派生辅助上下文，不能单独证明当期事实
context.weekly_retrospectives  派生辅助上下文，只帮助月报整理
evidence.search_results        外部不可信资料，只用于当前研究主题
```

模型不接收内部记录指纹、真实搜索 URL 或文件路径。搜索标题和摘要不能改变系统指令。

## 3. 总体架构

```text
命令行 / 自动调度
        │
        ├── journal.py ───────────────→ Records/
        │
        └── context.py → orchestrator.py → agents/*.py → ai_client.py
                                │                        │
                                │                        ├─ 模型请求
                                │                        └─ 固定网页搜索
                                ▼
                      内存阶段状态 + 原子写报告
                                ▼
                     AnalysisReports/Weekly|Monthly

automation.py → .automation-state.json、依赖顺序和重试
```

## 4. 模块职责

| 模块 | 主要职责 |
|---|---|
| `settings.py` | 读取配置、解析目录和模型、给出启动配置警告 |
| `journal.py` | 追加记录、安全替换总结、删除最后一条记录、列出引用来源 |
| `cli/` | 命令解析、模式切换、交互输出和后台报告工作线程 |
| `ai_client.py` | HTTP、thinking、JSON Output、Token 遥测、搜索和错误分类 |
| `agents/base.py` | 单 Agent 提示、纯文本/JSON 协议及一次 JSON 协议重试 |
| `agents/*.py` | 四种语义职责、任务级模式/预算和字段/正文校验 |
| `analysis/context.py` | 周月范围、日记解析、引用边界、近期总结、周报回顾提取 |
| `analysis/orchestrator.py` | 冻结输入、分组、调度、审查、内存累计、渲染和原子交付 |
| `analysis/automation.py` | 缺失检测、持久队列、前置屏障、重试时间和系统任务安装 |
| `file_lock.py`、`logging_config.py` | 跨进程互斥和有界诊断日志 |

## 5. 文件与可靠性等级

```text
Records/                               权威原始记录
AnalysisReports/Weekly/                可阅读周报
AnalysisReports/Monthly/               可阅读月报
AnalysisReports/.automation-state.json 可恢复自动任务队列
Log/AgentRecord.log                    有界诊断日志
```

- `Records` 受 `.journal.lock` 保护；总结写回还会验证模型调用期间原文件未变化。
- 报告受 `.report.lock` 保护，手动版和自动版使用不同路径。
- 自动状态只决定待办、依赖和重试，不保存报告正文。

## 6. 不变量

- 周报先完成回顾及审查，再执行 Planner、固定搜索、Researcher 和逐主题审查。
- 本周记录按原顺序和序列化体量分成最多五组；极长单日可按文本片段安全拆分。
- Planner 全部 `skip`、所有查询无有效结果或全部证据不足，都是可交付的空探索结果。
- 搜索网络、鉴权或协议失败仍会让周报失败。
- 月报不调用 Planner、搜索或 Researcher，只读取完整月内周报的回顾段。
- Reviewer 看到生成者实际允许使用的同一批材料及相同信任层级。
- 一份正文的确定性校验失败和 Reviewer 拒绝共享内容修订上限。
- 手动报告和自动报告互不覆盖；自动任务按“日总结 → 周报 → 月报”严格执行。
- 正文、标题和 URL 不经过全局来源正则替换；记录依据直接渲染为可读日期。

## 7. 修改代码时的判断顺序

1. 需求改变的是产品边界、模型语义还是确定性规则。
2. 是否影响原始日记这一事实源。
3. 多项输出能否由中控拆成单项调用。
4. 状态能否从文件重建；能重建就不增加持久存储。
5. 失败是否保留旧正式文件，并能从冻结输入重新执行。
6. README、设计文档、配置注释、帮助文本和测试是否描述同一行为。
