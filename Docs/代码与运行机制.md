# 代码与运行机制

产品边界见[设计基线](./设计基线.md)，模型契约见[各 Agent 功能与联动](./各Agent功能与联动.md)。

## 1. 入口与配置

`python main.py`、`python -m AgentRecord` 和打包程序最终进入 `AgentRecord.cli.entry.main`。常用系统参数为：

| 参数 | 行为 |
|---|---|
| `--run-automation` | 检查并执行到期任务 |
| `--retry-automation` | 独立进程重试失败任务 |
| `--install-automation` | 安装用户级调度 |
| `--uninstall-automation` | 卸载用户级调度 |

`settings.py` 读取应用目录中的 `config.yaml`。相对目录以配置文件所在目录为基准，`/m` 只原子更新 `current_model`。

DeepSeek V4 的默认 `max_tokens` 为 `100000`。这是单次生成上限，不是上下文窗口；具体 Agent 仍有更小的输入分块和正文长度限制。四个报告 Agent 请求 JSON Output，日记总结请求普通文本。

## 2. 日记写入

`journal.py` 是日记的唯一写边界。普通记录立即追加；总结只替换 `<summary>`；引用只扫描 `Records/*.md`。追加、总结替换和删除最后一条记录共用 `.journal.lock`，均不依赖 SQLite。

## 3. 报告生成

`analysis.orchestrator.generate_analysis_report` 只接受：

- `weekly`：回顾与审查完成后，中控分组，依次运行选题、固定搜索、单主题研究和单主题审查。
- `monthly`：只运行回顾与审查，不检查搜索配置。

中控限制单次 Agent 输入，必要时按原文顺序分块。模型调用、校验、审查、搜索和缓存都发生在写报告之前。报告先写唯一 `.tmp` 再原子替换；完成状态写库失败时恢复原文件。

## 4. 模型与搜索

`ai_client.py` 统一处理 OpenAI 兼容请求：

- JSON 任务在模型允许时发送 `response_format={"type":"json_object"}`；
- DNS、连接、超时、HTTP 408 和 5xx 使用有限请求重试；
- 429、鉴权、输出截断、内容过滤和资源不足分别分类；
- `stop` 但正文为空时只补答一次；
- 每次调用记录耗时、输入/输出/缓存 Token 和结束原因。

第三方搜索只由中控调用。Planner 和 Researcher 都不能自行联网，Researcher 也看不到 URL。

## 5. 自动任务

系统调度每分钟唤醒一次短进程，小时水位避免重复缺漏检测。任务严格按“昨日日记总结 → 上周周报 → 上月月报”消费持久队列；前项失败时后项等待。

网络与限流按 5 分钟重试。同输入的内容失败最多自动执行首次尝试和一次整点重试；输入、模型或搜索配置变化后可以重新尝试。周报失败重试可复用已验证阶段和搜索证据。

## 6. SQLite

数据库只含 `analysis_runs` 和 `agent_artifacts`，使用 WAL、外键、10 秒 busy timeout 和短事务。它只保存运行审计与阶段缓存，不参与普通记录写入，也不保存权威来源数据。

结构不一致时程序不迁移或覆盖旧文件。确认没有报告运行后，可以删除数据库及同名 `-wal`、`-shm`，下次运行自动创建空库。

## 7. 验证

```bash
python -m compileall -q AgentRecord tests
python -m unittest discover -s tests -v
```
