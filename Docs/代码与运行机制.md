# 代码与运行机制

本文描述 AgentRecord 当前实现。产品边界见[设计基线](./设计基线.md)，Agent 职责见[各 Agent 功能与联动](./各Agent功能与联动.md)。

## 1. 进程入口

`python main.py`、`python -m AgentRecord` 和 PyInstaller EXE 最终都调用 `AgentRecord.cli.entry.main`。

| 参数 | 行为 |
|---|---|
| 无 | 显示自动化状态并进入交互终端 |
| `--run-automation` | 检查并执行到期自动任务 |
| `--retry-automation` | 独立进程重试当前失败自动任务 |
| `--install-automation` | 安装用户级系统调度项 |
| `--uninstall-automation` | 卸载系统调度项 |

Windows 发布同时包含交互用 `AgentRecord.exe` 和无控制台的 `AgentRecordBackground.exe`。计划任务只启动后者。

## 2. 配置与路径

`settings.py` 是配置边界。源码运行使用仓库根目录 `config.yaml`；冻结运行使用 EXE 同目录配置。`diary_dir`、`analysis_dir`、`log_dir` 的相对路径以配置文件目录为基准。

配置版本为 3。自动任务只包含 `daily_summary`、`weekly_report` 和 `monthly_report`。周报要求 `third_search`；月报只总结，不检查搜索配置。旧配置中的 `daily_profile`、`daily_information` 和 `daily_information_time` 会被忽略。

模型密钥只进入请求头，不得写入日志、报告或测试输出。`/m` 原子更新 `current_model`。

## 3. 终端与日记写入

`cli.app` 维护记录/报告两种模式。`journal.py` 是 Markdown 的唯一写边界：

1. 回车提交时捕获一次时间；
2. 同一时间确定文件名、文件头和记录时间；
3. 普通记录立即追加并带隐藏边界标记；
4. 总结只原子替换 `<summary>`；
5. 引用只扫描 `Records/*.md`。

追加记录、替换总结和删除最后一条记录共用 `.journal.lock`。普通记录不访问 SQLite、模型或网络。

## 4. 报告生成

手动 `/a weekly`、`/a monthly` 在当前交互进程的单一工作线程中运行。`/retry` 启动分离进程，当前窗口退出不影响它。

公共中控 `analysis.orchestrator.generate_analysis_report` 按类型分支：

- `weekly`：Retrospective 回顾 → Reviewer → ResearchPlanner → 中控搜索 → Researcher → Reviewer → 两板块组装。
- `monthly`：Retrospective 回顾 → Reviewer → 单板块组装；不调用 Planner、Researcher 或第三方搜索。

报告先写唯一临时文件再原子替换。完成状态写库失败时恢复原报告，已有成功报告不会被失败运行覆盖。

旧 `Profile.md` 和 `Information/*.md` 不进入快照、提示、缓存键或报告生成。

## 5. 自动任务

类 Unix 安装 `@reboot` 和每分钟 cron；Windows 安装登录与每分钟任务。短进程用 `last_detection_hour` 保证每个新小时只做一次常规扫描。

执行顺序：

1. 获取 `.automation.lock` 内核锁；
2. 清理旧每日画像/信息任务的错误、队列和重试状态；
3. 核对昨日日记总结、最近闭合周报、最近闭合月报；
4. 将真实缺失目标加入持久队列；
5. 按日总结、周报、月报顺序消费；
6. 完成后写入小时水位并释放锁。

`.automation-state.json` 只保存水位、当前任务、待处理周期和失败分类。锁文件可以长期存在，文件存在不代表任务仍运行。

## 6. 模型与网络故障

`ai_client.py` 统一处理 OpenAI 兼容请求：

- DNS、连接、超时、HTTP 408 和服务端 5xx 在单次请求内最多三次；
- HTTP 429 交给自动任务按 5 分钟重试；
- 401/403 标记为配置错误；
- `length`、`content_filter` 和资源不足分别分类；
- `stop` 且 `message.content` 为空时，追加一次“输出完整最终答案”的补答请求；再次为空才返回失败；
- 周/月回顾和周报研究分别拥有有限结构修复与一次内容修订预算。

周报的第三方搜索由中控逐字执行 Planner 查询，分配 `W-*` 证据 ID。Researcher 看不到 URL，只选择证据 ID；中控最终渲染链接。月报没有联网阶段。

## 7. SQLite 与旧数据

SQLite 使用 WAL、外键、10 秒 busy timeout 和短 `BEGIN IMMEDIATE` 事务。当前新运行只允许 `weekly` 和 `monthly`，旧库中的 `daily_profile`、`daily_information` 审计行仍可保留读取。

若检测到紧邻旧版的画像表结构，程序仍会先备份数据库、导出 `Profile.md`、再移除旧表，避免升级时丢失数据；导出文件之后只作历史资料。

## 8. 验证清单

```bash
python -m py_compile $(rg --files AgentRecord tests -g '*.py')
python -m unittest discover -s tests -v
```

至少验证：周报仍输出两个板块、月报无探索且无搜索配置也能生成、旧每日失败状态被清理、空最终回答只补答一次、帮助与配置不再出现每日信息或画像入口。
