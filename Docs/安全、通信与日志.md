# MyRecord 安全、加密通信与日志设计

本文补全此前缺失的**关键设计说明**：服务端/客户端如何建立加密通信、如何签发并校验连接凭证、
服务端记录哪些日志，以及云端 AI（周报/月报）的设计与审核机制。这些细节此前在各 README 中
要么被弱化（TLS 只写“建议”）、要么未写清（日志/审核），本文给出准确、逐项的说明。

> 代码依据：`server/hub/`、`server/ai/`、`server/main.py`、`client/config.yaml`、`sync.py`。

---

## 1. 加密通信（强制 TLS，服务端签发自己的公钥）

这是**强制要求，不是可选项**：

- 服务端 `python -m server.main run` 在未配置 TLS 证书/密钥时会**直接拒绝启动**（打印禁止明文
  提示并退出，返回码 2）。明文 HTTP 始终被禁止。
- **服务端签发自己的公钥**：`python -m server.main cert` 用 cryptography 生成一张**自签证书**
  （同时具备 CA 能力，有效期 10 年）及对应私钥，写入 `server/data/tls/server.crt` 与
  `server.key`。`--ip`/`--dns`/`--cn` 指定证书 SAN，确保客户端连接的地址（IP/域名）在证书覆盖
  范围内。这张自签证书就是“服务端自签的公钥”，客户端用它来做链路加密与对服务端身份的验真。
- 客户端 `config.yaml`：
  - `server_url` 必须为 `https://…`；
  - `verify` 指向复制到本机的 `server.crt` 路径，用该证书（作 CA）校验收信。
- 全程 `ThreadingHTTPServer` 直接把监听 socket 用 `SSLContext(PROTOCOL_TLS_SERVER)` 包裹成
  直连 HTTPS，**无需反向代理**。

> 一个自然的疑问：既然是自签（自认证），如何防中间人？本方案的信任锚是“首次把 `server.crt`
> 拷贝到客户端并手动指向它”，即**信任首次分发（TOFU）**。首次配置时通过可靠渠道把证书送到
> 客户端，之后客户端的 `verify` 每次都对服务端证书做严格验真；任何人无法用另一张证书冒充。

## 2. 连接凭证（修改日记所需的“超长密码”）

- **签发**：`python -m server.main token create`（或 `rotate`，二者等价，都会覆盖旧 token）
  用 `secrets.token_urlsafe(32)` 生成一长串随机令牌（约 43 个 URL 安全字符，即用户所说的
  “类似超长的密码”），打印一次后即不再可见。
- **服务端只存哈希**：`token` 明文不落盘。`hub/auth.py` 用 `hashlib.scrypt`（加盐、
  `N=2^14`、常量时间 `hmac.compare_digest` 比较）存为 `scrypt$N$r$p$salt$hash`。即使数据空间
  泄露，也无法反推明文 token。
- **连接与修改都需要凭证**：客户端所有会联系服务端的操作（不只“修改”，任何鉴权接口）都要带
  `Authorization: Bearer <token>` + `X-Device-Id`（本机名）：
  - 推送（写入/修改日志）：`POST /api/sync/push`
  - 在线删除（修改日志）：`POST /api/entries/delete`
  - 拉取对账、长轮询扇出、状态、报告、AI 管理：`pull` / `longpoll` / `status` / `reports` /
    `admin/retry` / `admin/model`
- **无凭证 / 凭证错误**：客户端只能**本地记录**（写入本机 `Records/` 并不被服务端采纳），无法把
  修改传上服务端，也无法拉取/删除/查看云端数据。因此“修改日记内容需要服务器签发的一个凭证用于
  连接许可”在实现上就是这条 Bearer token 校验。
- **爆破防护**：连续鉴权失败（`_LOCKOUT_THRESHOLD=5`）会按 `X-Device-Id` **锁定 60 秒**，并写入
  日志（`auth_failed` / `auth_locked_out`）。
- **凭证模型**：**单一共享 token**——服务端只存一个有效凭证；`create`/`rotate` 签发并覆盖旧
  token，`revoke` 停用（所有客户端失去同步）。凭证不绑定设备，设备由各端 `X-Device-Id`
  自报本机名区分。

## 3. 服务端日志内容

服务端统一把日志写到 `server/data/Log/MyRecord.log`（`logging_config.py`：
`RotatingFileHandler`，单文件上限 5MB、保留最近 2 个备份）。所有服务端模块（`server.*` 树下
的 hub 与 ai）通过 `logging.getLogger(__name__)` 落在这一个 handler 上。

记录的事件包括（条目正文**不**入日志，见节末“不记录”）：

**① 客户端连接 / 鉴权情况**
- `auth_failed device=<设备> addr=<IP>`：凭证错误
- `auth_locked_out device=<设备> addr=<IP>`：连续失败被锁定
- `auth_missing_device addr=<IP>`：请求缺 `X-Device-Id`
- `status_request device=<设备> version=… entries=… tombstones=…`

**② 客户端对日志的修改情况（同步）**
- `sync_push device=<设备> sent=N accepted=N version=N`：推送了多少条、被采纳多少条
- `sync_delete device=<设备> date=… deleted=<entry_id> version=…`：谁在线删了哪条
- `sync_pull device=<设备> after=… version=… entries=… tombstones=…`
- `sync_longpoll device=<设备> after=… changed=…`
- `report_read device=<设备> rel=… bytes=…`、`reports_list device=<设备> kind=… count=…`

**③ AI 报告生成状况**
- `analysis_started run=<id> kind=… period=…..….`
- `agent_start / agent_completed run=<id> agent=report duration_ms=…
  total_tokens=… cached_tokens=…`（单次 Report Agent 调用）
- `agent_failed run=<id> agent=… error_type=…`
- `daily_summary_validation_failed date=… attempt=… problems=…`（日总结格式校验失败）
- `analysis_completed / analysis_failed run=<id>`（报告整体成败）
- `automation_retry_started / completed / failed`（`/retry` 触发）
- `analysis_validation_failed run=<id> …`（报告正文/引用确定性校验拦截）

**④ 自动任务调度**
- `automation_state_initialization_failed`、`automation_configuration_invalid`、
  `automation_retry_failed`、`scheduler` 相关的异常日志。

**日志记录原则（隐私保护）**
- **不记录私密原文**：条目正文、日记内容不进日志；
- **不记录模型密钥**：`api_key` 不写日志；`automation.py` 只存其哈希指纹
  `api_key_digest` 用于失败签名，且不落在日志明文；
- **不记录 token 明文**：鉴权只记设备名与结果。

## 4. 云端 AI 分析与报告生成（简化后）

> 权威报告设计见 [设计基线.md](./设计基线.md) 第 8 节。本节给出与安全/日志相关的内容要点。

### 4.1 无工具、无联网搜索、无 AI 审核

- Agent **不能读文件、不能写文件、不能访问数据库、不能调用任何工具**。
- **单次 Report Agent**：周/月报由**单次 Report Agent** 一次性直接读取本周期完整原始记录流并生成
  完整报告正文。**不再有**独立 reviewer、AI 修订链、中间摘要读入（近期总结/同期周报）。
- **唯一事实源**：报告只读本周期 `Records/YYYY-MM-DD.md` 完整原始记录流，不读每日总结、旧周报、
  旧月报或引用历史记录，避免“摘要层层传递”造成信息损失。

### 4.2 引用与来源表（中控确定性工作）

- 中控按日期分隔展示记录流，标注每条记录**所在日期文件的行号**（如“第 23 行”），并给全局引用编号
  `[N]`；Agent 在正文用 `[N]` 数字引用（如“完成了某项工作。[2]”）。
- **Agent 不生成来源表、不处理完整 `R-日期-行号` 格式**；它只引用输入中给出的 `[N]`。
- 生成后**中控**建立 `[N]↔R-日期-行号` 映射并生成文末来源表（如 `[2] R-20260819-23`）。

### 4.3 确定性校验（无 AI 审核）

中控**只做确定性校验**（不依赖模型）：

1. 正文格式：非空、不是 JSON、无代码围栏/包装标签/自行产出的完整 `R-日期-行号`。
2. 引用有效性：全部 `[N]` 为合法正整数且 1 ≤ N ≤ 本周期记录总数（即映射到本周期真实存在的原始记录）。

失败时中控附**确定性修正清单**让同一 Report Agent 有界重出，仍失败则整份报告失败、旧文件不动
（原子交付）。不再有任何 AI 审查/修订链。

### 4.4 统一生成与审计元数据

- **无手动/自动之分**：手动与自动用同一流程、同一报告路径
  （`Weekly/YYYY-MM-DD_to_YYYY-MM-DD.md`、`Monthly/YYYY-MM.md`）；手动重新生成直接覆盖原报告。
- 报告头部保留审计元数据：生成时间、使用模型、生成耗时、Token 用量、原始日记范围、run_id
  （全部来自中控确定性统计，不来自模型）。
- **每日总结保留但报告不依赖**：每日总结仍写 `<summary>`，有独立确定性格式校验（`daily_summary_retry_limit`）
  + 防陈旧写入（比对内容哈希）；报告不再读取每日总结。
- **自动任务**按依赖顺序执行（昨日日总结 → 上一自然周周报 → 上一自然月月报），失败进入
  `.automation-state.json`，可 `/retry` 按队列重试；网络/限流按 `retry` 配置退避。
