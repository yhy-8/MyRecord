# AgentRecord 设计与实现

根目录 `README.md` 负责安装和使用；本文只维护产品边界、Agent 契约和实现不变量。

## 1. 产品边界

AgentRecord 是本地优先的个人记录与周期回顾工具。原始 Markdown 日记是唯一事实源，AI 只生成可删除、可重建的总结和报告。

```text
日记原始记录
  └─ 昨日简短总结
          ↓
自然周报
  ├─ 整理与回顾
  └─ 记录驱动的领域研究
          ↓
自然月报
  └─ 整理与回顾
```

- 日记总结写入 `<summary>`，不联网，不创建独立报告。
- 周报先回顾，再从本周记录产生最多五个公开问题，固定搜索并逐主题研究。
- 月报只回顾，可参考完整落在当月内的周报，不选题、不搜索。
- 系统不生成分析日报、每日信息简报或人物画像，也不提供即时聊天、心理诊断、人格定性和行为教练。

## 2. 模型与中控

模型负责理解、总结、研究和审查。程序负责确定性细节：任务拆分与顺序、数组和编号、来源绑定、搜索与 URL、Markdown、文件写入、缓存、耗时和 Token 统计。

四个报告 Agent 使用同一 `current_model`，均不能直接访问文件、数据库或工具：

| Agent | 每次处理 | 最小 JSON 输出 |
|---|---|---|
| Retrospective | 一组周期记录或一个有序分块 | `{"text":"连续正文"}` |
| ResearchPlanner | 一个中控记录组 | `{"action":"search|skip","query":"单个问题或空字符串"}` |
| Researcher | 一个问题及其搜索摘要 | `{"status":"supported|insufficient","text":"正文或不足原因"}` |
| Reviewer | 一份回顾或一个研究主题 | `{"approved":true或false,"feedback":"一段意见或空字符串"}` |

输出只能包含约定字段和标量类型。模型不能创建多任务数组、嵌套小节、标题、来源 ID、URL 或 Markdown 结构；需要多个结果时由中控拆成多次单任务调用。日记总结只有一份 Markdown 正文，直接使用文本响应。

所有语义输出遵循“完整前提下简洁”。程序不在生成后按字符数截断或判废；结构、类型、来源和隐私校验仍然执行。`max_tokens=100000` 是请求开始前交给接口的异常输出与成本安全预算，不是目标篇幅。

## 3. 报告流程

周报严格执行：

```text
Retrospective → Reviewer
        ↓
中控把全部本周记录按日期分成最多五组
        ↓
每组 ResearchPlanner → 中控固定搜索
        ↓
每主题 Researcher → 每主题 Reviewer → 中控组装
```

Planner 每组只决定一个公开查询或跳过。中控分配 `Q-*`，过滤搜索结果并分配 `W-*`；Researcher 看不到 URL 或来源 ID。中控把记录组的全部 `R-*` 和主题的全部有效 `W-*` 绑定到正文。单个主题仍不合格时独立丢弃，至少一个主题通过即可交付。

月报只执行：

```text
Retrospective → Reviewer → 中控组装
```

Retrospective 输入过大时，中控按原文顺序分块，每块独立生成和审查后合并。字段或正文校验失败、或者 Reviewer 拒绝时，原 Agent 共享最多一次修订机会；无法解析的 JSON 和 API 错误直接结束当前阶段。

报告先写唯一临时文件再原子替换。只有文件交付和运行状态都成功才算完成；报告头由中控写入实际模型、耗时和本次输入、输出、缓存及总 Token。

## 4. 数据与权限

- 普通记录立即写入，不依赖模型、网络、SQLite 或自动任务。
- AI 不能修改原始记录；只有用户删除最后一条记录和程序替换 `<summary>` 可以改写日记。
- 新引用只能指向日记，不能指向派生报告。
- `journal.py` 是日记唯一写边界；追加、总结替换和删除共用 `.journal.lock`。

```text
Records/                            原始日记
AnalysisReports/Weekly/             周报
AnalysisReports/Monthly/            月报
AnalysisReports/.analysis.sqlite3   可删除的运行缓存
AnalysisReports/.automation-state.json  自动任务状态
Log/AgentRecord.log                 诊断日志
```

SQLite 只含：

- `analysis_runs`：报告类型、周期、来源、模型、输入哈希、状态、路径、错误和时间。
- `agent_artifacts`：Agent/搜索阶段、修订、载荷、错误、Token 和搜索遥测；唯一约束为 `(run_id, agent, revision)`。

数据库使用外键、WAL、10 秒 busy timeout 和短事务。它不保存权威数据，也不迁移旧结构；确认没有报告运行后可删除主文件及同名 `-wal`、`-shm`，下次运行自动重建。

## 5. 模型、搜索与故障

`settings.py` 从应用目录读取 `config.yaml`；相对路径以配置目录为基准，`/m` 只原子更新 `current_model`。

`ai_client.py` 对报告 Agent 请求 JSON Output；达到 `max_tokens` 时接口返回 `length`，程序将其视为不完整输出。连接、超时、HTTP 408 和 5xx 使用有限请求重试；429、鉴权、截断、过滤和资源不足分别分类；`stop` 但正文为空时只补答一次。

第三方搜索只由中控调用。周报必须配置可审计搜索；月报不依赖搜索。外部标题和摘要属于不可信输入，只能作为研究资料，不能作为指令。

## 6. 自动任务

系统调度每分钟唤醒一个短进程，小时水位避免重复检测。任务严格按以下顺序消费持久队列：

```text
昨日日记总结 → 上一完整自然周周报 → 上一完整自然月月报
```

前项失败时后项等待。网络与限流按 5 分钟重试；同输入的内容失败最多自动执行首次尝试和一次整点重试。输入、模型或搜索配置变化后可以重新尝试，周报可复用已验证阶段和搜索证据。

Linux 源码运行的 cron 必须由实际 Python 环境安装，使任务命令固定指向该解释器和实际目录中的 `main.py`。

## 7. 不变量与验证

- 周报始终包含回顾和研究；月报始终只有回顾。
- 月报不联网；周报研究必须来自本周记录。
- 模型不能决定文件结构、来源归属和执行顺序。
- 语义输出不能仅因篇幅较长而失败。
- AI 不替用户做价值判断或现实决定。

```bash
python -m compileall -q AgentRecord tests
python -m unittest discover -s tests -v
```
