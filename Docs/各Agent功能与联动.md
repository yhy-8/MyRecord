# 各 Agent 功能与联动

本文描述周报与月报中四个正式 Agent 的输入边界和联动关系。中控位于 `analysis.orchestrator`，AgentSpec 位于 `agents/`。所有 Agent 都不能直接写日记、报告或数据库。

## 1. 总体流程

```text
周报：
周期记录 + 日记引用 + 近期总结
          │
          ├─ Retrospective → 整理与回顾 → Reviewer
          │
          └─ 中控把全部本周记录分成最多五组
                    ↓
             ResearchPlanner（每组一次）
                    ↓
             中控固定搜索 + W-* 证据
                    ↓
               Researcher（每主题一次）→ Reviewer
                    ↓
             中控组装、来源索引、原子交付

月报：
周期记录 + 日记引用 + 近期总结 + 当月完整周报
                    ↓
             Retrospective → Reviewer
                    ↓
             中控组装、来源索引、原子交付
```

周报严格先完成回顾链路，再进入选题和研究链路；Planner 只读取本周记录，不把回顾正文当成新的事实输入。月报只运行回顾链路。所有 Agent 使用同一 `current_model`。

四个正式 Agent 都通过模型的 JSON 模式返回结果，但 JSON 只承担“结果类型 + 一段文本”的传输职责。多任务数组、任务编号、来源 ID、搜索、审查调度、排序和 Markdown 组装全部属于中控。日记顶部总结本身只有一份 Markdown 正文，不需要路由字段，因此仍直接请求文本。

## 2. 运行与输入快照

报告入口只接受 `weekly`、`monthly`。实际使用的标准日记记录登记为稳定来源 ID：

```text
R-YYYYMMDD-NNN-HHHHHHHHHHHH
```

运行快照包含：

- 本周期原始记录；
- 本周期记录明确引用的日记，最多十份且每份最多前 12000 字符；
- 周期开始前 30 天的日记总结；
- 月报额外读取完整落在该自然月内的同期周报；同周手动/自动版同时存在时优先手动版。

快照不读取每日信息简报或人物画像。月报读取周报只是复用二级整理，最终判断仍引用 `R-*`。

完整快照计算 SHA-256 并写入 `analysis_runs`。Retrospective 输入超过 120000 字符时，原始记录按约 30000 字符分块，每块分别生成和审查后合并。

## 3. Retrospective：整理与回顾

Retrospective 读取原始记录、日记引用、近期总结，以及月报可用的同期周报，但不能联网。一次调用只返回：

```json
{"text":"一份连续正文"}
```

`text` 可以自然分段，但不能包含模型自拟标题、列表、来源 ID 或 URL。输入过大时，中控先切成有序原文块，再对每块分别调用和审查；模型不负责创建或嵌套多个小节。

正文回顾事实、行动、决定与问题，并整理观点、理念、理想、关注领域和行为模式的变化。中控把该次调用的全部输入记录作为本段依据，并生成 Markdown 标题、引用标点和来源索引。内容不得把时间先后写成因果，不得心理诊断或给出行为教练式命令。

Retrospective 不生成或更新人物画像。

## 4. Reviewer：回顾门禁

Reviewer 不联网。中控把待审正文和该次调用绑定的记录集合交给它，使它检查：

- 事实与时期是否混淆；
- 是否把引用或 AI 内容当成用户立场；
- 来源是否覆盖核心判断；
- 是否出现因果越界、心理诊断、套话或行为教练。

Reviewer 每次只返回：

```json
{"approved":true,"feedback":""}
```

拒绝时 `approved=false` 且 `feedback` 必须是一段具体可修改意见。中控把意见交回原 Agent；同一正文最多修订一次。

## 5. ResearchPlanner：周报研究选题

ResearchPlanner 只在周报运行。中控按日期顺序把全部本周记录确定性分成最多五个连续组，每组单独调用 Planner。每次只返回：

```json
{"action":"search","query":"一个公开问题"}
```

没有合适问题时返回 `{"action":"skip","query":""}`。中控据此产生零至五个主题；如果全部跳过，研究阶段失败而不是让模型临时补题。每个保留主题：

- `origin` 固定为 `records`；
- 由中控绑定该记录组的全部本周 `R-*`；
- 查询必须去除邮箱、长数字、本地路径和可识别私人细节；
- 必须能通过公开资料实质研究。

它不能联网，不生成正文、候选数组、主题 ID、标题字段或来源列表。纯新闻热点和每日信息雷达不再是选题来源。

## 6. 中控检索与 Researcher

中控逐字执行 Planner 的固定查询，每个查询最多接受 10 条结果，过滤重复或非法 URL，并分配：

```text
W-Q001-001
```

Researcher 每次只看到一个问题，以及该问题检索结果的标题、摘要和日期；它看不到 URL、`W-*` 或 `R-*`，也没有工具权限。每次只返回：

```json
{"status":"supported","text":"一份连续研究正文"}
```

证据不足时返回 `status=insufficient` 和一段不足原因。`text` 不能包含标题、列表、来源 ID、URL 或引用标点。

中控使用固定查询作为三级标题，把该记录组的全部 `R-*` 和该主题的全部有效 `W-*` 绑定到正文，并把 URL 渲染为精确链接。无证据或 `insufficient` 主题可丢弃；全部主题都无可交付内容才终止周报研究阶段。

月报不会运行 ResearchPlanner、搜索或 Researcher。

## 7. Reviewer：研究门禁

Reviewer 对每个周报研究主题检查：

- 来源是否支持事实；
- 是否包含反例或适用边界；
- 记录与研究问题之间是否被夸大；
- 推断是否标注不确定性；
- 是否越权替用户做最终判断。

每个主题独立审查。被拒绝主题的意见只交回该主题的 Researcher，并最多修订一次；仍被拒绝时中控丢弃该主题。至少一个主题接受即可交付，其余主题不会被重写。

## 8. 组装与交付

周报：

```markdown
## 一、整理与回顾

...

## 二、领域探索与研究

...

## 来源索引
```

月报：

```markdown
## 整理与回顾

...

## 来源索引
```

两类报告的文件头都由中控加入使用模型、生成耗时和本次实际模型调用的 Token 用量。`R-*` 来源索引直接使用当前输入记录渲染，不依赖数据库来源目录。

文件先写唯一 `.tmp` 再原子替换。正文成功后才把运行标记为 `completed`；写库失败时恢复原报告。

## 9. 失败与重跑

Agent 调用、解析、字段校验和审查产物写入 `agent_artifacts`。无法解析的 JSON、API 错误或不完整响应立即使当前阶段失败，不用同一提示盲目重试。已经解析但字段/正文校验失败，或 Reviewer 拒绝时，共享最多一次修订机会；API 普通失败不进入内容修订。

接口 `finish_reason=stop` 但没有最终正文时，`ai_client` 会立即追加一次补答请求；第二次仍为空才失败。同周期报告可覆盖固定 Markdown 文件，每次运行仍有独立 SQLite 审计 ID。周报同输入失败重试可以复用已校验回顾、选题和搜索证据；月报只有回顾缓存。
