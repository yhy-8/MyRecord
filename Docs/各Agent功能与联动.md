# 各 Agent 功能与联动

本文描述周报与月报中四个正式 Agent 的输入边界和联动关系。中控位于 `analysis.orchestrator`，AgentSpec 位于 `agents/`。所有 Agent 都不能直接写日记、报告或数据库。

## 1. 总体流程

```text
周报：
周期记录 + 日记引用 + 近期总结
          │
          ├─ Retrospective → 整理与回顾 → Reviewer
          │
          └─ 已过审回顾 + 周期记录
                    ↓
             ResearchPlanner
                    ↓
             中控固定搜索 + W-* 证据
                    ↓
               Researcher → Reviewer
                    ↓
             中控组装、来源索引、原子交付

月报：
周期记录 + 日记引用 + 近期总结 + 当月完整周报
                    ↓
             Retrospective → Reviewer
                    ↓
             中控组装、来源索引、原子交付
```

周报第一板块由 Retrospective 生成，第二板块由 Researcher 生成。月报只运行回顾链路。所有 Agent 使用同一 `current_model`。

## 2. 运行与输入快照

报告入口只接受 `weekly`、`monthly`。实际使用的标准日记记录登记为稳定来源 ID：

```text
R-YYYYMMDD-NNN-HHHHHHHHHHHH
```

运行快照包含：

- 本周期原始记录；
- 本周期记录明确引用的日记，最多十份且每份最多前 12000 字符；
- 周期开始前 30 天的日记总结；
- 月报额外读取完整落在该自然月内的同期周报；同周手动/自动版同时存在时优先手动版。

快照不读取每日信息简报或人物画像。月报读取周报只是复用二级整理，最终判断仍引用 `R-*`。

完整快照计算 SHA-256 并写入 `analysis_runs`。Retrospective 输入超过 120000 字符时，原始记录按约 30000 字符分块，每块分别生成和审查后合并。

## 3. Retrospective：整理与回顾

Retrospective 读取原始记录、日记引用、近期总结，以及月报可用的同期周报，但不能联网。它只返回：

- 按小节组织的自然语言段落；
- 每段直接支持该判断的 `R-*` 来源选择。

正文回顾事实、行动、决定与问题，并整理观点、理念、理想、关注领域和行为模式的变化。模型不生成 Markdown 标题、引用标点或来源索引。内容不得把时间先后写成因果，不得心理诊断或给出行为教练式命令。

Retrospective 不生成或更新人物画像。

## 4. Reviewer：回顾门禁

Reviewer 不联网。中控只给它回顾正文实际引用的最小记录集合，使它逐项检查：

- 事实与时期是否混淆；
- 是否把引用或 AI 内容当成用户立场；
- 来源是否覆盖核心判断；
- 是否出现因果越界、心理诊断、套话或行为教练。

`pass=false` 必须给出具体可修改意见。中控把意见交回 Retrospective，最多使用一次实质内容修订；JSON、结构和来源校验另有最多两次修复。

## 5. ResearchPlanner：周报研究选题

ResearchPlanner 只在周报运行，读取本周记录和已过审回顾，自主选择一至五个公开领域问题。每个主题：

- `origin` 固定为 `records`；
- 必须带促成选题的本周 `R-*`；
- 查询必须去除邮箱、长数字、本地路径和可识别私人细节；
- 必须能通过公开资料实质研究。

它不能联网，也不生成正文。纯新闻热点和每日信息雷达不再是选题来源。

## 6. 中控检索与 Researcher

中控逐字执行 Planner 的固定查询，每个查询最多接受 10 条结果，过滤重复或非法 URL，并分配：

```text
W-Q001-001
```

Researcher 只看到主题及证据 ID、标题、摘要和日期，看不到 URL，也没有工具权限。它逐主题返回 `supported` 或 `insufficient_evidence`，并为事实段落选择准确的 `W-*`，为记录关联选择 `R-*`。

中控校验 ID 归属后，使用 Planner 原标题渲染三级标题，把 `W-*` 转成精确链接，并为推断添加 `[AI推断]`。无证据主题可丢弃；全部主题都无可交付内容才终止周报研究阶段。

月报不会运行 ResearchPlanner、搜索或 Researcher。

## 7. Reviewer：研究门禁

Reviewer 对每个周报研究主题检查：

- 来源是否支持事实；
- 是否包含反例或适用边界；
- 记录与研究问题之间是否被夸大；
- 推断是否标注不确定性；
- 是否越权替用户做最终判断。

至少一个主题接受时，中控丢弃被拒绝主题并交付其余内容；全部拒绝时才把意见交回 Researcher进行一次内容修订。

## 8. 组装与交付

周报：

```markdown
## 一、整理与回顾

...

## 二、领域探索与研究

...

## 来源索引
```

月报：

```markdown
## 整理与回顾

...

## 来源索引
```

两类报告的文件头都由中控加入使用模型、生成耗时和本次实际模型调用的 Token 用量。`R-*` 来源索引直接使用当前输入记录渲染，不依赖数据库来源目录。

文件先写唯一 `.tmp` 再原子替换。正文成功后才把运行标记为 `completed`；写库失败时恢复原报告。

## 9. 失败与重跑

Agent 调用、解析、结构校验和审查产物写入 `agent_artifacts`。周/月报告使用“最多两次结构修复 + 一次内容修订”的分离预算。API 普通失败不进入内容修订。

接口 `finish_reason=stop` 但没有最终正文时，`ai_client` 会立即追加一次补答请求；第二次仍为空才失败。同周期报告可覆盖固定 Markdown 文件，每次运行仍有独立 SQLite 审计 ID。周报同输入失败重试可以复用已校验回顾、选题和搜索证据；月报只有回顾缓存。
