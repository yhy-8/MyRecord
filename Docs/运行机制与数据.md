# AgentRecord 运行机制与数据

本文说明配置、文件写入、报告生命周期、自动队列和故障恢复。产品原则见[设计原则与系统架构](./设计原则与系统架构.md)，模型阶段见[Agent 与报告流程](./Agent与报告流程.md)。

## 1. 启动、配置与路径

源码入口是根目录 `main.py`，也可用 `python -m AgentRecord`。`settings.py` 从应用目录读取 `config.yaml`；相对数据目录以配置文件所在目录为基准。

主要配置：

- `current_model`、`models`：用户主动选择所有总结和报告使用的模型。
- `third_search`：周报固定搜索的地址、密钥、数量和超时。
- `retry`：内容修订、HTTP/空响应、自动暂停和等待策略。
- `automation`：总开关及日总结、周报、月报开关。

任务级 thinking 和 `max_tokens` 固定在代码中，不是用户配置。启动时会主动警告活动模型密钥为空，以及自动周报启用但搜索配置不可用。`/m` 只更新 `current_model`，不会自动升级模型。

## 2. 文件布局

```text
Records/YYYY-MM-DD.md
AnalysisReports/
  .automation-state.json
  Weekly/YYYY-MM-DD_to_YYYY-MM-DD_manual.md
  Weekly/YYYY-MM-DD_to_YYYY-MM-DD_auto.md
  Monthly/YYYY-MM_manual.md
  Monthly/YYYY-MM_auto.md
Log/AgentRecord.log
```

报告生成不创建或访问 SQLite。旧版本留下的 `.analysis.sqlite3`、`-wal`、`-shm` 不参与任何运行判断；确认没有旧版本报告进程后可自行删除。

## 3. 日记写入边界

所有日记修改集中在 `journal.py` 并共用 `.journal.lock`：

- 新记录立即追加到当天文件。
- 日记总结只替换 `<summary>...</summary>`。
- `/d` 只删除今日最后一条标准记录。
- `/ref` 只创建指向 `Records` 中日期日记的相对引用。

总结生成前保存完整日记哈希，模型返回后在锁内重新核对；文件发生变化则拒绝写入过时总结。summary 使用函数式正则替换，模型正文中的 `C:\Users`、`\1` 或 Markdown 反斜杠不会被解释为替换组。

## 4. 报告输入快照

`analysis/context.py` 确定自然周/月，读取周期内实际存在的日记，并从模型输入中省略同日旧 `<summary>`。

| 输入 | 用途 | 边界 |
|---|---|---|
| 当期原始记录 | 周报/月报主要事实 | 单次 Agent 总输入 120000 字符 |
| Retrospective 分块 | 超大周期按原顺序处理 | 每块记录目标 30000 字符 |
| 显式引用日记 | 用户明确引用的历史上下文 | 最多 10 个文件，单文件 12000、总计 30000 字符 |
| 近期总结 | 周期前连续背景 | 最多 30 天、总计 20000 字符 |
| 月内周报回顾段 | 月报派生辅助上下文 | 单份 12000、总计 30000 字符 |
| 搜索资料 | 周报单主题证据 | 每查询最多 10 条，标题/摘要受字段边界限制 |

这些是输入安全边界，不是报告输出长度目标。同一次运行读取完成后的 Python 数据结构就是冻结快照；阶段只在内存中流转。

## 5. 报告生命周期

手动和自动任务调用同一生成逻辑：

1. 计算周期、来源和目标路径，检查周报搜索配置。
2. 获取 `.report.lock`，防止并发报告任务。
3. 冻结记录、引用、近期总结和月报可用的周报回顾段。
4. 生成、校验和审查回顾；周报继续执行选题、搜索、研究和审查。
5. 在内存中累计当前调用的 Token 遥测并渲染 Markdown。
6. 写入本次 run ID 对应的同目录临时文件。
7. 原子替换正式目标文件；替换成功即代表交付。

任一模型、搜索、校验或文件错误都会结束本次运行。未替换的临时文件会清理，已有正式报告保持不变。日志写入不参与报告提交，不存在“报告已写好却因数据库状态失败而撤销”的补偿路径。

手动版与自动版路径不同，互不覆盖。run ID 由中控直接生成 UUID，只用于报告元数据、临时文件名和日志关联。

## 6. 锁与原子操作

| 机制 | 保护对象 | 行为 |
|---|---|---|
| `.journal.lock` | 日记追加、总结替换、删除 | 阻塞等待，串行修改原始日记 |
| `.report.lock` | 周报/月报生成和交付 | 非阻塞；已有任务时新任务提示忙碌 |
| `.automation.lock` | 一次自动调度循环 | 操作系统级互斥，避免短进程重叠 |
| 临时文件 + `replace` | 日记、报告、配置、自动状态 | 同目录写完整内容后原子替换 |

锁文件残留不代表仍被占用；互斥由操作系统锁状态决定。

## 7. 自动任务状态

`.automation-state.json` 是唯一持久运行状态，使用临时文件原子替换。它不保存报告正文或 Agent 输出，只保存：

- `pending_targets`：准确日期/周期队列。
- `errors`、`retry_after`、`retry_kind`：最近错误及重试类别。
- `failure_counts`、`failure_keys`、`failure_targets`：同输入失败次数和解锁签名。
- `current_task`、`current_task_detail`、`current_task_started_at`：状态展示。
- `last_detection_hour`、检查开始/完成时间：调度水位。

缺失目标先入队再运行，所以进程退出、跨午夜或被前置失败阻塞时，任务仍指向最初发现的日期。

## 8. 自动调度顺序

Linux cron 每分钟启动一个短进程。每小时只扫描一次新缺失项，但每分钟都可继续处理已到重试时间的队列。

```text
昨日日记总结 → 上一完整自然周周报 → 上一完整自然月月报
```

前项失败、被阻塞或未到重试时间时，后项不能越过。成功或发现真实产物存在后出队。`/retry` 使用同一依赖顺序。

自动完成只看真实产物：日记 `<summary>` 是否有内容，或准确 `_auto.md` 报告是否存在。手动报告不能替代自动报告。

## 9. 故障分类

| 故障 | 行为 |
|---|---|
| 连接、DNS、超时、HTTP 408/5xx | 请求层有限指数重试；之后由自动队列等待 |
| HTTP 429 | 不快速重试，交给自动调度等待 |
| 401/403、缺少模型/搜索密钥 | 配置阻塞，等待配置变化或 `/retry` |
| `length`、内容过滤 | 当前阶段失败，不使用残缺正文 |
| `insufficient_system_resource` | 作为临时网络/服务失败 |
| `stop` 但 content 为空 | 最多补答一次 |
| JSON 无法解析 | 最多一次协议重试，再失败则结束阶段 |
| JSON 字段/正文校验或 Reviewer 拒绝 | 原语义任务按共享上限有限修订 |
| Planner `skip`、Researcher `insufficient` | 合法语义结果，不重试 |
| 无主题、无有效结果、全部证据不足 | 周报成功并写明空探索原因 |
| 搜索服务错误 | 周报失败并按网络/配置类别处理 |
| 报告原子写失败 | 保留旧报告，不重新调用模型 |

同一输入内容失败达到 `retry.automation_content_failure_limit` 后自动暂停。输入、模型、重试策略或周报搜索配置变化时失败签名改变，可重新尝试。

## 10. 第三方搜索

每个 Planner 查询只搜索一次，结果数量受配置和程序上限 10 共同约束。程序验证 URL scheme、控制字符和规范化去重，为有效结果分配内部 `W-*` 编号。

Researcher 和 Reviewer 只看到相同的标题、摘要、日期与信任层级，不看到真实 URL。最终 Markdown 链接由中控从已验证结果渲染。月报完全不使用搜索。

## 11. Linux 自动任务部署

使用实际运行环境安装：

```bash
/home/a/miniconda3/envs/aiagent/bin/python main.py --install-automation
```

安装器用当前 `sys.executable` 和应用目录写入 `@reboot` 与每分钟 cron。移动目录或更换 Python 后，应先卸载再用目标解释器安装：

```bash
/home/a/miniconda3/envs/aiagent/bin/python main.py --uninstall-automation
```

## 12. 诊断、更新与验证

1. 用 `/status` 查看准确目标、当前任务、阻塞项和重试类别。
2. 查看 `Log/AgentRecord.log` 的 run ID、阶段和错误类型；日志不保存私密原文。
3. 检查目标 summary 或 `_auto.md` 文件是否真实存在。
4. 检查 cron 是否指向实际目录和 `aiagent` 解释器。
5. 修正配置或输入后使用 `/retry`；下一次报告从冻结输入实时生成。

代码变更后的最低验证：

```bash
/home/a/miniconda3/envs/aiagent/bin/python -m compileall -q AgentRecord tests
/home/a/miniconda3/envs/aiagent/bin/python -m unittest discover -s tests -v
```
