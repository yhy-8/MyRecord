# MyRecord 部署指南

本文说明服务端与客户端的完整部署步骤：开放什么端口、注意什么、如何签发设备凭证、
如何做数据备份/恢复与日常运维。配置语义见[运行机制与数据](./运行机制与数据.md)。

现状是**两端架构**：服务端是数据中枢 + 云端 AI（Linux 部署，原单机 `main.py` 已删除，
请勿使用旧入口）；客户端是薄记录端（Windows 桌面，也可在其他平台跑）。

---

## 1. 端口与网络

| 端口 | 方向 | 用途 |
|---|---|---|
| **8765** | 服务端监听 | 同步中枢接口；默认 http 明文，配置 `server.tls.*` 后直接以 **HTTPS（TLS）** 直连 |

服务端 `server/config.yaml` 中 `server.port` 默认 `8765`，`server.host` 默认 `0.0.0.0`
（监听所有网卡）。客户端 `client/config.yaml` 中 `client.server_url` 默认
`http://localhost:8765`，需要把它改为服务端的实际访问地址（启用 TLS 后为 `https://…`）。

### 防火墙 / 安全组

- **本机 Linux 服务器**：放行 8765 入站（或只让反向代理所在进程访问）。
  示例（firewalld / ufw）：
  ```bash
  sudo firewall-cmd --permanent --add-port=8765/tcp && sudo firewall-cmd --reload
  # 或 ufw： sudo ufw allow 8765/tcp
  ```
- **云服务器（云厂商安全组）**：如在阿里云/腾讯云/AWS 等，除系统防火墙外，还要在云
  控制台的安全组里放行对应端口。
- **建议**：公网一定要用 **HTTPS（TLS）**（见 5 节）。否则令牌与日记正文在公网明文
  传输会被窃听。你只需**服务端直连自签证书 TLS** 即可，无需反向代理。

## 2. 服务端部署（Linux + systemd）

依赖：Python ≥ 3.10，`pip install -r requirements.txt`（`pyyaml`、`requests`）。

```bash
cd <server工程根>            # 含 server/ 子目录的独立工程根
pip install -r server/requirements.txt
python -m server.main run    # 前台启动，Ctrl-C 退出（先验证能否跑通）
```

验证通过后接入 systemd 常驻。仓库自带单元文件 `server/deploy/myrecord-server.service`：

```bash
sudo cp server/deploy/myrecord-server.service /etc/systemd/system/
# 编辑该单元，把 ExecStart 的解释器路径与 WorkingDirectory 改成实际绝对路径
sudo systemctl daemon-reload
sudo systemctl status myrecord-server   # 确认 active (running)
```

服务启动后自带**每分钟后台线程**做自动 AI 任务（日总结→周报→月报），无需额外 cron。
若不用 systemd，也可直接用 `nohup python -m server.main run &`，但推荐 systemd（自动重启、
开机自启）。

检查是否正常启动：`sudo journalctl -u myrecord-server -n 30`。

### 长期常驻 / 开机自启 / 自动拉起

- **开机自启**：上面用的是 `systemctl enable --now`，已把服务设为开机自动启动，长期跑
  无需每次手动。
- **崩溃自动拉起**：单元内已含 `Restart=on-failure` + `RestartSec=3`，进程异常退出会自动
  重启，配合自带的每分钟 AI 调度线程即可长期运行。
- **改生效**：任何单元或工程路径调整后都要 `sudo systemctl daemon-reload`，再
  `sudo systemctl restart myrecord-server`。
- **WSL 环境（本仓库在 Windows 挂载盘上）**：若在 WSL2 里跑服务端，先确认 systemd 已启用：
  新建/编辑 `/etc/wsl.conf` 写入
  ```ini
  [boot]
  systemd = true
  ```
  然后 `wsl --shutdown` 再 `wsl` 重启 WSL，`systemctl is-system-running` 应不再报
  “not running”。之后按上文安装单元即可。（Windows 重启后需重新 `wsl` 进入；WSL 用
  宿主机端口转发，具体地址看 `wsl hostname -I`。）

## 3. 服务端 AI 配置（必须先填）

服务端 `server/config.yaml` 里必须先填好模型密钥，否则自动任务会失败：

- `models[].api_key`：模型 API 密钥（如 DeepSeek）。模型密钥**只在服务端**，不进数据空间、
  不进日志。
- `automation.*`：日总结 / 周报 / 月报开关，默认全开。

## 4. 签发链接凭证（单一共享 token）

鉴权是**长令牌**，服务端只存令牌的 scrypt 哈希，不存明文，令牌**只在签发时显示一次**。

**关键设计：凭证不绑定设备。** 服务端只存在**唯一一个链接凭证**，只要你持有这个 token，
用任意一台设备的客户端都能连上服务端同步（所以只需签发一次即可）。设备身份由各端
客户端**自报本机名**区分（如电脑名 `MK8`、手机默认名 `vivo y78`），每条记录都会带上
这个设备名，用于正确区分是哪个设备写的。

服务端签发（在服务端工程内；每次签发都会**覆盖并删除旧 token**，旧凭证立即失效）：

```bash
# 签发/重新签发唯一链接凭证
python -m server.main token create --device 任意标签
# 输出：
#   device_id: <标签>（仅用于管理展示）
#   token: <一长串随机令牌>   ← 复制保存，服务端只存它的哈希
```

把拿到的 token 写入客户端工程内的 `client/credentials.json`。格式参考**样板**
`client/credentials.example.json`：

```json
{
  "token": "<将这里的说明文字替换成服务端签发的 token>"
}
```

可选：若不想用本机名作为设备名，可在其中再加 `"device_id": "你想要的设备名"`；
留空或省略则自动使用本机名（如 `MK8`、`vivo y78`）。

写入后启动客户端 `python -m client`，首次启动会自动完整同步（拉取对账 + 冲刷离线队列 +
同步报告）。**没有写 token 或离线时，客户端也照常本地记录**，拿到 token 上线后按内容生成
一致的 entry_id 自动统一合并，各设备的记录按设备名区分。

### 凭证生命周期管理

```bash
python -m server.main token list                        # 查看当前唯一凭证状态
python -m server.main token rotate --device 标签          # 重新签发（覆盖旧 token，打印新 token）
python -m server.main token revoke --device 标签          # 停用凭证（所有端都无法同步）
```

- `rotate` 与 `create` 等价：都是签发新 token 并覆盖旧的。令牌疑似泄露时用它，拿到新
  token 后更新所有客户端的 `credentials.json`。
- `revoke`：停用凭证；因为凭证唯一共享，停用会让所有客户端都失去同步能力。

⚠️ **注意**：`credentials.json` 是链接凭证，等同密钥，**不要提交进仓库**（已在
`.gitignore` 中排除）、不要发给他人。`credentials.example.json` 是仅供参考的样板，可以提交。

## 5. 客户端部署 & 加密传输（自签证书 TLS 直连）

客户端是薄端，直接跑 Python 即可：

```bash
cd <client工程根>
pip install -r client/requirements.txt
# 编辑 client/config.yaml：把 server_url 改为服务端实际地址
python -m client
```

### 先澄清一件事：反代到底是什么？

你可能担心“用反代是不是意味着服务端签发的凭证不安全”。**不是。** 设备令牌（scrypt 哈希、
只在签发时显示一次）就是鉴权手段，本身是安全的。反代和 TLS 与凭证安全**无关**——它们解决
的是**传输加密**：在公网上用明文 HTTP，令牌和日记正文会被中途窃听。之前文档把反代当作
“不加改造就上 HTTPS”的省事办法，仅此而已。

**你完全可以不走反代，直接服务端自签证书直连 TLS**，更简单，也不依赖 Nginx/Caddy。

### 方法：自签证书 + 服务端直连 TLS（推荐，无反代）

1. **生成自签证书**（在服务端工程内）：
   ```bash
   # 生成 <data_dir>/tls/server.crt 与 server.key；--ip 一定要加上客户端会连接的
   # 服务器地址（公网 IP / 局域网 IP），否则客户端会因证书覆盖不到该地址而校验失败。
   python -m server.main cert --ip 1.2.3.4 --ip 127.0.0.1
   ```
2. **服务端启用 TLS**：编辑 `server/config.yaml`：
   ```yaml
   server:
     tls:
       certfile: "./data/tls/server.crt"
       keyfile:  "./data/tls/server.key"
   ```
   重启服务后 8765 即直接以 HTTPS 提供同步接口（无需反向代理）。
3. **客户端直连并校验收信**：编辑 `client/config.yaml`，把 `server_url` 改为 `https`，并把
   刚才生成的 `server.crt` 拷到客户端，`verify` 指向它：
   ```yaml
   client:
     server_url: "https://你的服务器IP:8765"
     verify: "./server.crt"        # 用于校验自签证书；留空 = 明文/不校验
   ```

`verify` 语义：为空时不校验收信（用于 http 明文或内网信任环境）；填证书路径时，requests 会
用该证书校验服务端身份，防止中间人窃听。证书有效期 10 年；到期后按步骤 1 重新生成并替换，
同时更新各客户端的 `verify` 路径。

## 6. 数据备份与恢复

数据空间（`data/`）是唯一事实源，定期备份。仓库自带脚本：

```bash
# 备份：默认备份到 <工程根>/backups，保留最近 7 份
server/deploy/backup.sh [备份目录] [保留份数]

# 恢复：从备份还原整个 data 空间（会覆盖当前数据，脚本会二次确认）
server/deploy/restore.sh <备份文件.tar.gz>
```

建议把 backup.sh 加入 crontab 每日执行，并把 backups 放到独立磁盘/对象存储上。

## 7. 部署后自检清单

1. 服务端 `systemctl status myrecord-server` 为 active；
2. `curl http://localhost:8765/api/status`（或反代域名）返回服务端状态；
3. 已签发设备凭证并写入对应客户端 `credentials.json`；
4. 客户端 `python -m client` 能启动并完成首次同步，写入一条记录能即时到达服务端
   `data/Records/`；
5. 服务端已填模型密钥，`/status` 显示自动任务可正常调度；
6. 公网已启用 HTTPS，未直接把 8765 明文暴露出去；
7. 已配置每日备份。
