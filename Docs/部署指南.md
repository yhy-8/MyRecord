# MyRecord 部署指南

本文说明服务端与客户端的完整部署步骤：开放什么端口、注意什么、如何签发设备凭证、
如何做数据备份/恢复与日常运维。配置语义见[运行机制与数据](./运行机制与数据.md)。

现状是**两端架构**：服务端是数据中枢 + 云端 AI（Linux 部署，原单机 `main.py` 已删除，
请勿使用旧入口）；客户端是薄记录端（Windows 桌面，也可在其他平台跑）。

---

## 1. 端口与网络

| 端口 | 方向 | 用途 |
|---|---|---|
| **8765** | 服务端监听 | 同步中枢 HTTP 接口（push / pull / longpoll / delete / status / reports / admin） |
| 443（或反向代理端口） | 公网 → 服务端 | 若用 Nginx/Caddy 做 HTTPS 反代，将 HTTP 8765 转发到 443 |

服务端 `server/config.yaml` 中 `server.port` 默认 `8765`，`server.host` 默认 `0.0.0.0`
（监听所有网卡）。客户端 `client/config.yaml` 中 `client.server_url` 默认
`http://localhost:8765`，需要把它改为服务端的实际访问地址。

### 防火墙 / 安全组

- **本机 Linux 服务器**：放行 8765 入站（或只让反向代理所在进程访问）。
  示例（firewalld / ufw）：
  ```bash
  sudo firewall-cmd --permanent --add-port=8765/tcp && sudo firewall-cmd --reload
  # 或 ufw： sudo ufw allow 8765/tcp
  ```
- **云服务器（云厂商安全组）**：如在阿里云/腾讯云/AWS 等，除系统防火墙外，还要在云
  控制台的安全组里放行对应端口。
- **强烈建议**：不要让 8765 直接暴露公网明文。用反向代理做 **HTTPS（TLS）**（见 5 节）。令牌
  与服务端鉴权传输应当走加密通道，否则在公网上会被窃听。

## 2. 服务端部署（Linux + systemd）

依赖：Python ≥ 3.10，`pip install -r requirements.txt`（`pyyaml`、`requests`）。

```bash
cd <server工程根>            # 含 server/ 子目录的独立工程根
pip install -r server/requirements.txt
python -m server.main run    # 前台启动，Ctrl-C 退出（先验证能否跑通）
```

验证通过后接入 systemd 常驻。仓库自带单元文件 `server/deploy/myrecord-server.service`：

```bash
sudo cp server/deploy/myrecord-server.service /etc/systemd/system/
# 编辑该单元，把 ExecStart 的解释器路径与 WorkingDirectory 改成实际绝对路径
sudo systemctl daemon-reload
sudo systemctl enable --now myrecord-server
sudo systemctl status myrecord-server   # 确认 active (running)
```

服务启动后自带**每分钟后台线程**做自动 AI 任务（日总结→周报→月报），无需额外 cron。
若不用 systemd，也可直接用 `nohup python -m server.main run &`，但推荐 systemd（自动重启、
开机自启）。

检查是否正常启动：`sudo journalctl -u myrecord-server -n 30`。

### 长期常驻 / 开机自启 / 自动拉起

- **开机自启**：上面用的是 `systemctl enable --now`，已把服务设为开机自动启动，长期跑
  无需每次手动。
- **崩溃自动拉起**：单元内已含 `Restart=on-failure` + `RestartSec=3`，进程异常退出会自动
  重启，配合自带的每分钟 AI 调度线程即可长期运行。
- **改生效**：任何单元或工程路径调整后都要 `sudo systemctl daemon-reload`，再
  `sudo systemctl restart myrecord-server`。
- **WSL 环境（本仓库在 Windows 挂载盘上）**：若在 WSL2 里跑服务端，先确认 systemd 已启用：
  新建/编辑 `/etc/wsl.conf` 写入
  ```ini
  [boot]
  systemd = true
  ```
  然后 `wsl --shutdown` 再 `wsl` 重启 WSL，`systemctl is-system-running` 应不再报
  “not running”。之后按上文安装单元即可。（Windows 重启后需重新 `wsl` 进入；WSL 用
  宿主机端口转发，具体地址看 `wsl hostname -I`。）

## 3. 服务端 AI 配置（必须先填）

服务端 `server/config.yaml` 里必须先填好模型密钥，否则自动任务会失败：

- `models[].api_key`：模型 API 密钥（如 DeepSeek）。模型密钥**只在服务端**，不进数据空间、
  不进日志。
- `automation.*`：日总结 / 周报 / 月报开关，默认全开。

> 周报已移除联网检索，不再需要任何搜索密钥配置。

## 4. 签发设备凭证（如何签发 device_id / token）

设备鉴权是**长令牌**，服务端只存令牌的 scrypt 哈希，不存明文。因此令牌**只在签发时显示
一次**，务必立即保存到客户端，否则无法找回。

服务端签发（在服务端工程内）：

```bash
# 为某台设备创建一个令牌，会打印 device_id 与 token，两者都要保存
python -m server.main token create --device "我的笔记本"
# 输出示例：
#   device_id: d7f4...
#   token: <一长串随机令牌>
#   令牌只显示一次，请妥善保存（服务端只存哈希）。
```

将拿到的 `device_id` 和 `token` 写入客户端工程内的 `client/credentials.json`：

```json
{
  "device_id": "d7f4...",
  "token": "<一长串随机令牌>"
}
```

写入后启动客户端 `python -m client`，首次启动会自动完整同步（拉取对账 + 冲刷离线队列 +
同步报告），并按命令提示使用。

### 令牌生命周期管理

```bash
python -m server.main token list                        # 列出所有已注册设备
python -m server.main token rotate --device "我的笔记本" # 轮换该设备令牌（旧令牌作废，打印新令牌）
python -m server.main token revoke --device "我的笔记本" # 停用该设备（吊销）
```

- `rotate`：设备丢失/令牌疑似泄露时用；拿到新令牌后更新对应 `credentials.json`。
- `revoke`：弃用设备时吊销，防止旧设备继续同步。

⚠️ **注意**：`credentials.json` 是设备身份凭证，等同密钥，**不要提交进仓库**（已在
`.gitignore` 中排除）、不要发给他人。若仓库历史里已出现过该文件，请立即 `rotate` 该令牌。

## 5. 客户端部署 & 加密传输

客户端是薄端，直接跑 Python 即可：

```bash
cd <client工程根>
pip install -r client/requirements.txt
# 编辑 client/config.yaml：把 server_url 改为服务端实际地址
python -m client
```

生产环境**必须启用 HTTPS**，否则公网上凭据会被窃听。两种常见做法：

- **反向代理 TLS**（推荐）：Nginx/Caddy 在公网监听 443 并做 TLS 终止，把请求转发给本地
  8765，并把 `server_url` 设为 `https://你的域名`。
- **自签证书 + 服务端直连 TLS**：需要改造服务绑定，通常不如反代省事。

启用 HTTPS 后，客户端 `client/config.yaml`：

```yaml
client:
  server_url: "https://your.domain"   # 换成你的域名/公网地址
```

## 6. 数据备份与恢复

数据空间（`data/`）是唯一事实源，定期备份。仓库自带脚本：

```bash
# 备份：默认备份到 <工程根>/backups，保留最近 7 份
server/deploy/backup.sh [备份目录] [保留份数]

# 恢复：从备份还原整个 data 空间（会覆盖当前数据，脚本会二次确认）
server/deploy/restore.sh <备份文件.tar.gz>
```

建议把 backup.sh 加入 crontab 每日执行，并把 backups 放到独立磁盘/对象存储上。

## 7. 部署后自检清单

1. 服务端 `systemctl status myrecord-server` 为 active；
2. `curl http://localhost:8765/api/status`（或反代域名）返回服务端状态；
3. 已签发设备凭证并写入对应客户端 `credentials.json`；
4. 客户端 `python -m client` 能启动并完成首次同步，写入一条记录能即时到达服务端
   `data/Records/`；
5. 服务端已填模型密钥，`/status` 显示自动任务可正常调度；
6. 公网已启用 HTTPS，未直接把 8765 明文暴露出去；
7. 已配置每日备份。
