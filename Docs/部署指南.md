# MyRecord 部署指南

本文是简明的**操作步骤**。代码结构见 [代码结构.md](./代码结构.md)，安全/加密/日志/AI 的
权威设计见 [设计基线.md](./设计基线.md)。两端架构：服务端是数据中枢
+ 云端 AI；客户端是薄记录端。二者**严格分离、各自独立部署**：只有极少
代码重合（原子写入、日记文件格式）各自内置一份，互不导入、不共用 `common/`。部署默认使用
**自签证书 TLS 直连**（无需反向代理）。

> 两个强制前提：① **加密是必须的**（服务端未配置 TLS 会拒绝启动）；② **修改/同步日志必须携带
> 服务端签发的连接凭证**（无凭证只能本地记录）。

---

## 1. 服务端部署（Linux + systemd，HTTPS 直连）

前置：Python ≥ 3.10。

```bash
cd <server工程根>                      # 含 server/ 子目录的独立工程根（从这一层运行 python -m server.main）
pip install -r server/requirements.txt
cp server/config.example.yaml server/config.yaml    # 用模板生成运行配置，再在其中填入模型 api_key
python -m server.main cert --ip 服务端公网IP --ip 127.0.0.1   # 生成自签证书
python -m server.main run              # 前台启动验证（TLS 未配置会拒绝启动）
```

> `config.example.yaml` 是提交的**配置模板**（api_key 留空）；运行时读取的是 `config.yaml`
> （含 api_key，已 gitignore，不入版本库），请务必复制模板后**填入你的模型密钥**。

常驻（systemd，一键）：

```bash
sudo python -m server.main deploy
sudo journalctl -u myrecord-server -n 30   # 确认日志
```

> `deploy` 自动带出当前解释器与工程根、按需生成自签证书，写入服务端单元与备份单元/定时器后执行
> `systemctl daemon-reload && systemctl start myrecord-server`，并 `systemctl enable --now
> myrecord-backup.timer`。服务端仅启动、不启用开机自启动（如需开机自启请自行 `systemctl enable`）；
> 备份定时器已启用，每周自动备份。

服务端证书路径不写入 `config.yaml`：`cert` 统一生成到 `./data/tls/server.crt/.key`，
`run` 固定从该处读取并**强制 TLS**，证书缺失时拒绝启动（提示先执行 `cert`）。

## 2. 签发链接凭证（单一共享 token）

凭证是**唯一共享 token**，不绑定设备：只要你持有它，任意客户端都能连上同步。签发会
**覆盖并删除旧 token**。

```bash
python -m server.main token create
# 输出：token: <一长串随机令牌>   ← 复制保存（服务端只存它的哈希）
# 再次执行会提示覆盖确认（输入 yes）；旧 token 立即失效。
```

把 token 写入客户端 `client/credentials.json`（格式见样板 `client/credentials.example.json`）：

```json
{
  "token": "<将说明文字替换成服务端签发的 token>"
}
```

凭证管理：

```bash
python -m server.main token list      # 查看当前是否已配置有效凭证（含生成时间）
python -m server.main token create    # 重新签发（覆盖旧 token，需输入 yes 二次确认）
```

凭证是**连接许可**：客户端所有同步与修改（推送、在线删除、拉取、状态、报告、AI 管理）都需携带
`Bearer <token>`；无凭证或凭证错误时只能本地记录，无法把修改传上服务端或拉取/删除云端数据。

⚠️ `credentials.json` 是密钥，勿提交进仓库（已 gitignore）；`credentials.example.json` 是样板可提交。

## 3. 客户端部署

```bash
cd <client工程根>
pip install -r client/requirements.txt
cp client/config.example.yaml client/config.yaml   # 用模板生成运行配置,再填入服务端地址
python -m client
```

编辑 `client/config.yaml`（由 `config.example.yaml` 复制而来）：

```yaml
client:
  server_url: "https://服务端IP:8765"   # 启用 TLS 后必为 https
  verify: ""                            # 默认=不校验收信（省事，自签直连；仍加密，但不验服务器身份）
```

> **`verify` 校验收信**：留空 `""` 为**默认**（关闭证书校验——自签直连省事，连接仍是 HTTPS 加密，但不验证服务器身份，有中间人风险）。
> 要**严格校验收信**只需两步：① 把服务端生成的 `server.crt` 拷到客户端；② 把这行改为 `verify: "./server.crt"`。此后每次连接严格验真，建议正式使用采用。

无 token 或离线时客户端也照常本地记录，上线后自动同步。

## 4. 数据备份

数据空间 `server/data/` 是唯一事实源，定期备份：

```bash
server/deploy/backup.sh [备份目录] [保留份数]   # 默认 backups/，保留最近 7 份
crontab -e                                        # 建议每日定时执行 backup.sh
```

> 备份机制详见 [设计基线.md](./设计基线.md) §10。`python -m server.main deploy` 已自动安装并启用
> 每周自动备份定时器（`myrecord-backup.timer`）；上述命令用于手动/临时备份。

---

## 5. 部署后自检清单

1. `systemctl status myrecord-server` 为 active；
2. `python -m server.main token create` 完成且 token 已写入各客户端 `credentials.json`；
3. 客户端 `python -m client` 能启动、完成首次同步、写入一条记录能即时到达服务端 `data/Records/`；
4. 服务端已填模型密钥，自动任务能调度；
5. 全程 HTTPS（自签证书直连）已生效。
