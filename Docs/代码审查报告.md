## 一、逻辑错误 / 会导致实际故障的问题

### 1. 根目录 `main.py` 已失效（优先级最高，直接影响启动与打包）

`main.py` 内容仍是旧包入口：

```python
from AgentRecord.cli.entry import main
```

但重构后 `AgentRecord/` 包已被删除（git 暂存区显示 `AgentRecord/... -> server/ai/...` 重命名且 `cli/` 删除）。
实测：

```
python main.py
→ ModuleNotFoundError: No module named 'AgentRecord'
```

连锁影响：
- `README.md` 中“运行 `python main.py`”的启动方式失效。
- `.github/workflows/build.yml` 用 `pyinstaller --onefile ... main.py` 打包
  `AgentRecord.exe` / `AgentRecordBackground.exe`，入口已损坏，即使打包成功启动即崩溃。
  且该 workflow 仍是旧单机逻辑，与新的服务端/客户端两端架构不符。
- `Docs/运行机制与数据.md` 写“源码入口是根目录 `main.py`，也可用 `python -m AgentRecord`”，均已过时。

建议：删除 `/main.py`（或改为引导 `client`），并把真实入口写入文档与打包脚本：

```text
服务端：python -m server.main run      # 另附子命令 token/import/render
客户端：python -m client               # 交互记录 + 同步
```

### 2. 其它核心逻辑

未发现阻断性逻辑错误。逐项确认一致：
- `server/main.py` 用后台线程每分钟调用 `ai_analysis.run_due_automatic_tasks()`，与 cron/systemd
  语义一致；同一时刻多实例因 `.automation.lock`（非阻塞）只会有一个真正执行。
- 端口：server 默认 `8765`，client 默认 `http://localhost:8765`，一致。
- `server/ai/analysis/context.py`、`orchestrator.py`、`automation.py` 之间导入与函数名严格对应；
  `__init__.py` 的导出与实际定义一致。
- 报告输入边界（120000 字符、分块 30000、近期总结、引用、周报回顾、搜索字段上限）均在代码中体现。
- tombstone / 删除 / 拉取 / 对账 / 防复活逻辑闭环，`tests/test_server_hub.py` 覆盖。
