# AgentRecord 设计基线

## 1. 产品边界

AgentRecord 是本地优先的个人记录与周期回顾工具。原始 Markdown 日记是唯一事实源，AI 只生成可删除、可重建的总结和报告。

```text
日记原始记录
  └─ 昨日简短总结
          ↓
自然周报
  ├─ 整理与回顾
  └─ 记录驱动的领域研究
          ↓
自然月报
  └─ 整理与回顾
```

系统不生成分析日报、每日信息简报或人物画像，也不提供即时聊天、心理诊断、人格定性和行为教练。

## 2. 三类输出

### 日记总结

总结写入对应日记顶部的 `<summary>`，只用于快速浏览。它是一份普通 Markdown 正文，不联网、不创建独立报告。

### 周报

周报固定包含：

1. 整理与回顾：总结本周事实、进展、问题、关注变化和有记录依据的行为模式。
2. 领域探索与研究：从本周记录产生最多五个公开问题，固定搜索后分别研究，至少保留一个通过审查的主题。

研究必须由本周记录引出，不能补入纯新闻热点。外部事实、适用边界、反例和推断应能区分。

### 月报

月报只做整理与回顾，不选题、不搜索、不运行 ResearchPlanner 或 Researcher。它可以参考完整落在当月内的周报，但事实判断仍以原始记录为准。

## 3. 模型与中控的分工

模型负责理解、总结、研究和审查；程序负责确定性细节：

- 任务拆分与调用顺序；
- 数组、编号和来源绑定；
- 搜索执行与 URL 管理；
- Markdown 标题、链接和来源索引；
- 文件写入、缓存、计时和 Token 统计。

四个报告 Agent 均使用 JSON Output，但每次只返回一个由字符串或布尔值构成的最小对象。模型不得创建多任务数组、嵌套小节、来源 ID 或 Markdown 结构。需要多个结果时，中控拆成多次单任务调用。

周报顺序固定为：

```text
回顾 → 审查 → 分组选题 → 固定搜索 → 逐主题研究 → 逐主题审查
```

月报顺序固定为：

```text
回顾 → 审查
```

## 4. 来源与权限

- AI 不能修改原始记录；只有用户删除最后一条记录和程序替换 `<summary>` 可以改写日记。
- 新引用只能指向日记，不能指向会被覆盖的派生报告。
- 日记记录由程序分配稳定的 `R-*`；周报搜索证据由程序分配 `W-*`。
- Retrospective 和 Reviewer 可以读取中控提供的记录；ResearchPlanner 只读取当前周的分组记录；Researcher 只读取一个问题及其搜索摘要。
- 所有 Agent 都不能直接访问文件、数据库或工具。

## 5. 存储与自动化

```text
Records/                         原始日记
AnalysisReports/Weekly/          周报
AnalysisReports/Monthly/         月报
AnalysisReports/.analysis.sqlite3  可删除的运行缓存
AnalysisReports/.automation-state.json  自动任务状态
Log/AgentRecord.log              诊断日志
```

自动任务只包含昨日日记总结、上一完整自然周周报和上一完整自然月月报，并严格按这个顺序执行。前项失败时后项不得越过。

周报和月报文件头由程序写入实际模型、生成耗时和本次模型调用的 Token 用量。SQLite 不属于权威数据，不提供旧结构迁移；删除后不影响日记和已有报告。

## 6. 不变量

- 记录写入不依赖模型、网络、SQLite 或自动任务。
- 周报始终包含回顾和研究；月报始终只有回顾。
- 月报不依赖搜索配置；周报必须使用可审计的固定搜索。
- 模型输出不能决定文件结构、来源归属和执行顺序。
- AI 不替用户做价值判断或现实决定。
