# AgentRecord 设计基线

> 状态：产品与架构基线，更新于 2026-08-05。

## 1. 产品定位

AgentRecord 是本地优先的个人记录、阶段回顾与周度领域研究系统：

```text
每天自由记录
  └─ 日记顶部简短总结
          ↓
自然周报
  ├─ 整理与回顾
  └─ 记录驱动的领域探索与研究
          ↓
自然月报
  └─ 整理与回顾（可参考当月完整周报）
```

原始 Markdown 日记是唯一事实源。系统整理事实、来源、变化和探索性推断，但不替用户做价值判断或现实决定。

## 2. 交付物边界

### 2.1 每日层

- 用户日记：标准 Markdown 原始记录流。
- 日记总结：写入日记顶部 `<summary>`，只用于快速浏览。

系统不生成分析日报、每日信息简报或人物画像。短周期联网收集缺乏稳定复用价值，人物画像又会把可从原始记录重建的判断固化成额外状态；两者均不再进入自动任务或报告输入。

旧版本生成的 `AnalysisReports/Information/` 和 `AnalysisReports/Profile.md` 不再使用，升级时可自行删除。

### 2.2 周报

周报固定包含两个一级板块。

第一板块“整理与回顾”包括：

- 本周事实、行动、决定、问题与进展；
- 观点、理念、理想和关注领域的形成、延续、变化或冲突；
- 有记录依据的行为模式观察。

行为模式属于基于记录的回顾，不得扩展成心理诊断、人格定性或行为教练建议。

第二板块“领域探索与研究”包括：

- 从本周记录得到的一至五个公开研究问题，数量由材料和研究价值决定；
- 外部事实、反例、适用边界、相邻概念和不同视角；
- 明确标注不确定性的探索性推断。

每个保留主题使用 ResearchPlanner 给出的标题作为独立三级标题。记录来源、外部证据、分析与推演放在对应标题下。主题必须由本周记录引出，不能补入纯新闻热点。

### 2.3 月报

月报只包含“整理与回顾”，不创建研究主题、不联网搜索，也不输出“领域探索与研究”板块。它读取当月原始记录、日记引用、近期总结，以及完整落在当月内的同期周报作为二级整理材料；事实判断仍回到 `R-*` 原始记录来源。

### 2.4 质量定义

- Retrospective 只返回语义段落和来源选择；Markdown 标题、引用与来源索引由中控生成。
- 周报研究由 ResearchPlanner 选题、Researcher 写作，第三方搜索由中控固定执行。
- 回顾和研究分别由 Reviewer 审查事实、时期、身份、来源、因果越界和表达。
- 用户记录使用稳定 `R-*` 来源标记；周报外部证据使用中控分配的 `W-*`。
- 记录、外部事实和 AI 推断明确分开。
- 月报不因缺少搜索配置而失败。
- 周报和月报文件头直接显示使用模型、生成耗时和本次模型调用的 Token 用量。

## 3. 原始记录与引用

普通输入在回车提交时只捕获一个本地时间，用它同时确定文件名、文件头和记录时间。断网、模型或数据库失败不得阻止记录追加。

AI 不能修改原始记录；只有用户删除最后一条记录和程序原子替换 `<summary>` 可以改写日记。新引用只能选择日记，不能引用会被覆盖的派生报告。历史报告引用文本保留，但分析上下文不读取其目标。

## 4. 数据分层

```text
原始事实层
  Records/YYYY-MM-DD.md

周期交付层
  AnalysisReports/Weekly/*_manual.md | *_auto.md
  AnalysisReports/Monthly/*_manual.md | *_auto.md

派生状态层
  AnalysisReports/.analysis.sqlite3
  AnalysisReports/.automation-state.json

诊断层
  Log/AgentRecord.log

```

`.analysis.sqlite3` 只保存可丢弃的运行状态与失败重试缓存；删除后可从日记和报告文件恢复正常使用，不迁移旧结构。

## 5. 交互基线

记录模式：

```text
普通文字                   立即追加到今日日记
/v [日期]                  查看日记
/ref [日期]                按日期选择并引用日记
/d                         删除今日最后一条记录
/c                         清空终端显示
/h                         显示帮助
/mode                      切换到报告模式
```

报告模式：

```text
/s [日期]                  生成日记顶部总结
/a weekly [日期]           生成手动周报
/a monthly [日期]          生成手动月报
/retry                     独立后台重试失败自动任务
/m                         永久切换模型
/status                    查看自动任务状态
/h                         显示帮助
/mode                      返回记录模式
```

## 6. 自动化可靠性基线

计划任务每分钟唤醒一次短进程，小时水位确保每个新小时只做一次常规缺漏检测。自动任务严格按“昨日日记总结、上周自动周报、上月自动月报”执行。

- 旧状态中的 `daily_profile` 和 `daily_information` 错误、队列与重试字段在读取后清除。
- 日总结、周报和月报由真实文件内容证明完成。
- 休眠或关机后，下一分钟按小时水位补查。
- 自动化锁由内核持有，进程退出或崩溃后自动释放。
- 网络、限流、鉴权、内容和结构失败分别分类；网络与限流按 5 分钟重试，同输入内容失败最多自动尝试两次。
- 模型返回 `finish_reason=stop` 但最终正文为空时，客户端立即追加一次明确的最终答案请求；再次为空才失败。
- 周报可复用同输入、同模型和同搜索配置下已校验的阶段与搜索证据；月报没有搜索阶段。
- 缺失目标的确切日期或周期进入持久队列，失败的前项不会让后项越过依赖顺序。

## 7. 明确不做

- 不提供 `@AI` 即时聊天。
- 不要求用户把日记填写成结构化表单。
- 不生成分析日报或每日信息简报。
- 不维护人物画像或画像反馈。
- 不允许新记录引用报告。
- 不建设通用知识图谱、自由讨论式 Agent 群或行为教练。
- 不让月报重复周报的联网探索。
- 不让 AI 静默修改用户原文或替用户做最终判断。

## 8. 变更完成条件

- 周报仍有独立的回顾与研究板块；月报只有回顾板块。
- 每日信息、每日画像、画像反馈入口和对应自动任务均不存在。
- 旧每日状态不会继续显示或阻塞现有三项自动任务。
- 月报在没有第三方搜索配置时可生成；周报仍要求可审计搜索。
- 周报和月报文件头包含模型、耗时和 Token 用量。
- README、帮助文本、配置注释、设计文档和代码一致。
- 记录写入不依赖模型、网络、SQLite 或自动任务锁。
- 相关测试、静态编译和最小运行检查通过。
